# 外部情报对比 · 2026-10

> 调研时间：2026-10-18。来源：GitHub 近期提交/issue、HN、V2EX、linux.do、技术博客。
> 本文只记录**与本 fork 的差异**和**据此做的决定**，不重复已知实现。
> 证据分级：**实测** = 有代码/抓包/可复现对照；**个案** = 单人单次经历；**推测** = 只有设计意图或二手转述。

## 一、五条最重要的发现

### 1. 「部署拓扑」比出口 IP 更致命（实测，最有价值）

sub2api #7386（2026-09-23）里 ghost1025 的对照：两个实例出口都是住宅 IP ——
**A 直接部署在住宅 IP 机器上 → Max 账号稳定；B 国内部署再代理到同一个住宅 IP → 几天就封。**

> 中间多一跳本身就是可探测特征，换 IP 解决不了。

这条对我们最不利：**本 fork 的部署形态天生就是"中间一跳"**。代码层面无法修复，只能改变部署位置。

### 2. IP 纯净度被高估（个案，但方向一致）

V2EX 1232292（2026-08-05）：美家宽 + 美卡 + 满额使用，升 5x 第二天封；同一个人另一批**机房 IP**、十几个号、含 5 个 Pro，半年零封。

另一条：同帖回复里，稳定半年后**新增第三个地区节点**，几天内封；退回单节点即恢复。

> 真正的信号更像「出口数量 + 地区跳变 + 是否被多人共用」，而不是「机房 vs 住宅」。

### 3. 设备/客户端遥测在源码级被审计出来了（实测，最强证据）

`claude-telemetry-audit`（2026-10）的结论：

- Android 把 `ANDROID_ID` 明文交给 Sift，**即使用 VPN 也上报公网 IPv6**
- CLI 每请求带设备标识、**工作目录原文路径**、系统提示词里的 **git 提交者与邮箱**、本地时区

> 这意味着：**同一台机器服务多个账号，上游可以在内容层把这些串起来**，而我们目前的画像只按凭证统计，完全没有这个维度。

### 4. 封禁可能沿「项目」传播（个案，n=1 近似对照）

linux.do 2861527（2026-09-05）：干净的 WSL 环境跑 Claude Code，**打开某个老项目约 1 小时内封**；换新项目则正常。作者据此推翻"清设备就安全"。

> 如果成立，同批凭证服务同批老项目会**集体引爆**——而我们的画像按凭证隔离，看不到这层关联。

### 5. 429 是前兆（个案，1 源）

locdd 101388（2026-10-16）：同一批 CPA 反代号里，只有**一个号反复"429 拉不到额度"**，几天后封。"429 之后突然封号基本等于提前宣判。"

> 我们目前把 429 当普通限流处理，没有语义化成"该凭证进入观察期"。

## 五、两个必须说清的边界

**1. 没有任何公开复盘把封号定位到单一原因。**
包括本文引用的所有案例。所谓"某手段一定有效"在这个问题上不存在，本 fork 的所有闸都是"降低证据强度"，不是"消除判定"。

**2. 有些维度在服务端补不上。**
设备 ID、本地路径、git 提交者邮箱、支付方式、KYC 国家——这些由客户端和账号本身携带。服务端能做的只有：**不要把不同账号串起来**（T-15），以及**不要把同一个账号暴露成多个形态**（已有）。

## 附录：遥测主张的实测复核（2026-10-19）

论坛帖 `macos.do/t/topic/266` 的作者主张：「没遥测启用，特征非常明显。封号是一定的事情。」

在真机上用真客户端做了三次抓包（本机 CLI 2.1.280，Claude Pro）：

| 配置 | 结果 |
|---|---|
| 原样（`settings.json` 里有 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`） | 无 `event_logging` |
| 用 `--settings` 去掉该开关 | 无 `event_logging` |
| 再把 `~/.claude.json` 的 `metricsStatusCache.enabled` 强制为 true | 无 `event_logging` |

三次会话都真实调用了上游（`/v1/messages` 200，含工具调用），访问的主机只有
`api.anthropic.com`、`mcp-proxy.anthropic.com`、`registry.npmjs.org` 与本地 MCP。

**结论**：至少在这台机器、这个账号、这类负载下，**真实客户端本身就不发遥测**。
所以"没有遥测"不能作为判定代理的证据；该主张的最强形式（必封）未被复现。

这不代表遥测信号为零——真实用户多数不会关闭遥测，长期为空的账号仍是弱异常。
但按当前的证据强度，**维持"不伪造遥测"的决定**：伪造要匹配 device id、账号 id、
env 块与 build time，任何一处不对就从"合法静默"变成"遥测在撒谎"。

## 附录二：macos.do 论坛帖核查（2026-10-19）

### 帖 280《ClaudeCode 2.1.30x 版本风控》——**属实**，已用二进制核对

作者 `065778` 称新版加了 `cc_gateway` 与 `x-claude-code-wiggly-dove`。下载
`@anthropic-ai/claude-code-darwin-arm64@2.1.303` 解包后统计字符串：

| 标识 | 2.1.280 | 2.1.303 |
|---|---|---|
| `cc_gateway` | 0 | 2 |
| `x-claude-code-wiggly-dove` | 0 | 3 |
| `tengu_wiggly_dove` | 0 | 2 |
| `cc_project` | 0 | 4 |
| `cc_turn_index` | 0 | 2 |
| `cc_prompt_id` | 4 | 4 |
| `cc_workload` | 4 | 4 |

2.1.303 里 billing header 的拼装：

```js
`x-anthropic-billing-header: cc_version=${y}; cc_entrypoint=${P};${g}${we}${Oe}${De}${Le}${He}${Ne}${Fe}${Ke}`
```

`cc_gateway` 的判定：

```js
L = I?.url ?? ANTHROPIC_BASE_URL
Ue = L !== undefined && (!URL.canParse(L) || isVouchedHost(url)) || hostVerdict
Fe = (gateway || te) && !Ue ? ` cc_gateway=${te ? "1" : "env"};` : ""
```

即：**基址不是白名单域名时，客户端会在 billing header 里写 `cc_gateway=env`**。

**对本项目的处置**：我们的身份是 2.1.280，天然不含这些字段；同时已禁止转发
`x-claude-code-wiggly-dove`（`claudeVersionGatedHeaders`）——一个 2.1.280 的请求
不可能携带 2.1.30x 才有的头，转发它既自我矛盾，也把别人签的校验值挂在自己名下。

**待办**：2.1.303 的 TLS/计费头/cch 需要重新抓包复验；当前台账仍是 2.1.280。

### 帖 210《anthropic 的追踪 SUB2API 技巧》——指出的 bug 我们没犯

作者指出 sub2api 重算 `cc_version` 后缀时按 **UTF-8 字节**取 text[4]/[7]/[20]，
官方是 JavaScript 的 **UTF-16 下标**，中文/emoji 开头时结果不同（`d80` vs `fdc`）。

我们的实现按 UTF-16 代码单元取值，且已用真实请求复算 MATCH。

### 帖 233《封了四五个号 总结出来的封号规律》——可执行的三条

1. **IP 看历史不看类型**：住宅 IP 也可能因历史行为被标记；机房 IP 质量可能更高。
   判断方法：用该 IP 试注册新号，被拦就是垃圾 IP。
2. **时区必须与 IP 一一对应**，Claude 会抓本地时区（与我们 T-13 一致）。
3. **客户端有安装码**：装 Claude 时生成唯一码随请求上传，不清干净会让两个号关联。
   该码在彻底清理后会变化，说明不是硬件绑定。

另附必须与 Claude 同出口的域名清单（代理分流用）：

```
anthropic.com  clau.de  claude.ai  claude.com
claudemcpclient.com  claudemcpcontent.com  claudeusercontent.com
servd-anthropic-website.b-cdn.net  sentry.io  statsigapi.net
cdn.anthropic.com  mcp.anthropic.com  console.anthropic.com
workbench.anthropic.com  anthropic.auth0.com
anthropic-com.ghost.io  anthropic.com.cdn.cloudflare.net
```
